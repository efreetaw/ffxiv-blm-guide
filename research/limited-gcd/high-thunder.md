# 第一题：只剩 1—13 个 GCD，高闪雷什么时候值得打？

研究日期：2026-10-22。场景已确认：**目标死亡或消失时，伤害到此截止。**

**先得到一个有条件的结论：没有旧雷、这一发雷只替换一发火4时，至少跳7次才赚。** 按每个GCD 2.5秒、还剩完整的N个GCD窗口计算，现在打雷：剩1—7个GCD不赚，剩8个看跳伤时机，剩9—13个能稳定赚。这里的“赚”是威力账本上的收益，不是每次暴击、直击后的实际伤害必然更高。

这个结论不能直接推广为“剩9个GCD一定要补雷”。终盘还要看它会挤掉什么：一发火4值540，一发绝望值630，耀星值900；若插雷改变了后续能打出的技能，应该比较整段输出。

## 1. 先固定这一轮计算的条件

- 单目标，100级；目标当前没有雷DoT，现在可以使用高闪雷。
- 从现在 `t=0` 开始，第一发可以立刻按；技能窗口依次是 `0、2.5、5.0……` 秒。
- 剩N个**完整**GCD窗口，定义伤害截止时间为 `T=N×2.5秒`。例如N=8表示还能输出20秒，最后一个窗口从17.5秒开始。
- 咏速420、无黑魔纹；先采用理想的2.5秒间隔，不计FPS与操作延迟。雷的命中延迟保留为模拟器中的0.757秒。
- 双方天语及其他伤害倍率一致；沿用注释版不含共同天语倍率的威力账本，不计团辅、爆发药与暴击直击的随机差异。
- 先比较“一发雷替换一发其他技能，剩余动作不变”。资源变化、移动收益、插入能力技收益，只有确认会改变后续输出时才另外计入。

**“还能按N次技能”并不自动等于“还剩N×2.5秒”。** 如果目标在最后一发按下后0.5秒就消失，应使用那个实际截止时间；按下了但没命中的技能也不能算伤害。下面的表只对应上述完整窗口定义。

- [BLM.ts](https://github.com/xivintheshell/xivintheshell/blob/08eb81788c343a684fd421a7955a4f0785f61868/src/Game/Jobs/BLM.ts#L962-L973)：高闪雷瞬发、0蓝耗、直伤150、命中延迟0.757秒；需要并消耗THUNDERHEAD。`thunderConfirm`给每跳60，状态持续30秒。
- [GameState.ts](https://github.com/xivintheshell/xivintheshell/blob/08eb81788c343a684fd421a7955a4f0785f61868/src/Game/GameState.ts#L315-L333)：DoT沿每3秒一次的公共事件节奏跳伤，并非从每次施法开始重新等3秒。首次事件由 `timeTillFirstManaTick + dotTickOffset` 决定；雷在命中时才挂上DoT。
- [GameConfig.ts](https://github.com/xivintheshell/xivintheshell/blob/08eb81788c343a684fd421a7955a4f0785f61868/src/Game/GameConfig.ts#L433-L444)与[XIVMath.ts](https://github.com/xivintheshell/xivintheshell/blob/08eb81788c343a684fd421a7955a4f0785f61868/src/Game/XIVMath.ts#L137-L142)：咏速也影响DoT威力，不能只改GCD秒数而一直按每跳60计算。本题420咏速的DoT倍率恰为1。

计算依据为上述固定上游版本的规则；计算脚本只检查公式和表格，不绑定本地源码文件。虽然BLM类有名为 `thunderTickOffset` 的字段，这个版本实际注册普通雷跳伤时使用的是父类的 `dotTickOffset`。

**版本边界：注释版是7.2账本，本地模拟器声明为7.5规则。** 本题采用二者一致的高闪雷威力，并借用固定模拟器版本的命中延迟与跳伤模型；未将7.5完整模拟结果当作7.2实测，也没有据此改写攻略。

## 3. 正收益的门槛是“新增伤害超过少掉的伤害”

先设雷在截止前跳了k次，被替换技能的威力为C，且其他动作都不变：

```text
雷的威力 = 150 + 60k
收益 Δ = 150 + 60k − C
正收益要求 Δ > 0；打平不算正收益。
```

| 只替换这一发，其他输出不变 | C | 至少需要几跳 |
| --- | ---: | ---: |
| 原本只能空转 | 0 | 直伤命中就有收益 |
| 冰3（按注释版290）/ 冰4 | 290 / 300 | 3 |
| AF1火3 | 406 | 5 |
| 以Q作平均线比较 | 526.615… | 7 |
| AF3火4 / 悖论 | 540 | 7 |
| AF3绝望 | 630 | 9；8跳恰好打平 |
| 异言 / AF3耀星 | 890 / 900 | 跳满750也不够 |

这些是**纯替换门槛**。冰3、冰4、火3通常承担进冰、回蓝、获得冰针、进火等作用；不能只看表格就删掉它们。火4还产生星极魂，悖论也影响后续资源，因此实际机会成本C可能不是该技能面板威力。

Q是长期基准循环的平均值，适合做第一道筛选。终盘没有保证还能补齐一个完整基准循环，最终应使用该局面真正少掉的输出。

**8个GCD是需要分清比较对象的边界。** 这时平均雷威力是534.86，比Q高8.24，却比火4低5.14。按均匀相位模型，约41.43%的相位能跳7次，其余跳6次。因此，“超过基准平均线”不等于“替掉火4一定赚”。

算表方法：令 `L = min(30, T−0.757)`，即命中后还剩多少秒能跳伤。对于不与命中、消失同刻的跳伤事件，跳数为 `floor(L/3)` 或 `ceil(L/3)`；均匀相位下平均跳数为 `L/3`。若直伤尚未命中就截止，整发雷记0。超过30秒不再增加跳数。

## 5. 应该放在第几个GCD？

如果没有旧雷、没有加成变化、不会改变其他技能的可用性和输出，**越早打，截止前的跳数越多或相同**；晚打不会凭空增加收益。

在上述2.5秒模型中，第j个位置打雷后，包含这一发在内还剩 `N−j+1` 个窗口。若只替换火4：

- 还剩至少9个窗口：稳定正收益。N=9、10、11、12、13时，分别最晚放在第1、2、3、4、5个位置。
- 还剩8个窗口：看相位，6跳亏30，7跳赚30。
- 还剩不超过7个窗口：不够超过火4。

更精确地，若雷命中后距离下一跳还有δ秒（通常在0—3秒之间），第7跳发生在：

```text
按下雷的时刻 + 0.757 + δ + 6×3 秒
```

这一时刻必须早于目标消失。从按下雷算起，**剩余时间不超过18.757秒时来不及7跳；超过21.757秒时可保证7跳；中间看相位**。恰好与命中、跳伤或目标消失重合的事件，需要按实际事件顺序判定，本表不声称验证这些同刻边界。

## 6. 两种会改变结论的情况

### 目标身上已经有雷

要扣掉被覆盖的旧雷原本还能造成的伤害。相同加成下，对比“不再补雷”：

```text
Δ = 150 + 60×（新雷跳数 − 因覆盖损失的旧雷跳数） − 其他技能的损失
```

旧雷损失只数**新雷命中后、目标消失前，旧雷本来还会跳的次数**；命中前已经跳出的部分是共同项。若旧雷本来就能覆盖到目标消失，且新旧每跳伤害一样，刷新没有新增DoT收益，只多150直伤。在其他动作不变时，这不足以替换火4。

### 插雷改变了后续循环

应在同一起始状态、同一截止时间下，对比两条合法序列：

```text
总收益 = 打雷方案在截止前的全部伤害 − 不打雷方案在截止前的全部伤害
```

例如雷占掉一格，导致最后一发耀星来不及命中，损失就不是一个Q。反过来，若原本因移动只能空转，雷能够命中就是额外输出。少打一发火4是否还保得住耀星，也必须检查，不能在删掉第6发火4后继续把它解锁的耀星算进去。

因此，完整优化问题的输入至少要包括：**剩余秒数与GCD进度、旧雷剩余时间、AF/UI档位、MP、冰针、星极魂、悖论、火苗、通晓、雷可用状态，以及会用到的能力技冷却**。其中“这一发雷是否值得打”和“它最晚能放在哪一格”都依赖这些条件。
